# Steam Input and hosted Xbox games

Valve's client can select a controller layout for an AppID. Native Steam Input games consume named actions and action sets through `ISteamInput`. Legacy games can consume controller or keyboard and mouse events produced by a Steam Input layout. Valve's XInput guidance describes how games can associate an emulated gamepad index with a Steam Input handle. [ISteamInput](https://partner.steamgames.com/doc/api/isteaminput) · [Gamepad emulation](https://partner.steamgames.com/doc/features/steam_controller/steam_input_gamepad_emulation_bestpractices)

## Shared controller design

The Xbox input path has three parts: sample a controller, route input to the foreground session, and deliver it through the API the game consumes. The WWA host and native presenter publish the same controller packet. SDL and XInput read a complete packet and acknowledge it after applying it. The wire layout stays compatible with existing game packages. Hosted games receive a gamepad by default. The package explicitly selects the existing pointer mode for the legacy Dwarf Fortress profile. In WWA, a secondary pad can open the Steam overlay while the game keeps its primary pad. [Shared packet](../runtime/shared/sdl-host-protocol.h) · [Native host](../runtime/presenter/hosted-input.cpp) · [WWA routing](../ui/signin/steam-sdl-gamepad.js)

Use the authenticated Steam client as the layout owner. Native Steam Input games should use Valve's action API and the game's action sets. For legacy gamepad emulation, correlate Steam's controller handle with the gamepad slot using `GetControllerForGamepadIndex`. Once the Xbox runtime exposes verified remapped output for that slot, feed it into the shared packet as that slot's only source. Route Steam-generated keyboard and mouse output to the existing keyboard and pointer paths. Use physical input where Steam Input is disabled. Keep Big Picture navigation and configuration notifications on the UI path.

Valve's Windows legacy emulation uses Steam Overlay hooks to supply emulated controller input. GabeBox's running-game menu and native WGI mailbox currently provide the foreground controls and physical input path. Verify a Steam-owned handle and observable remapped output for one legacy caller before changing the publisher. [Valve's gamepad emulation documentation](https://partner.steamgames.com/doc/features/steam_controller/steam_input_gamepad_emulation_bestpractices)

## Console verification

1. For a legacy gamepad caller, use the stock Steam layout editor to swap A and B. Launch through Big Picture. Capture the session's controller slot, Steam configuration selection, host mailbox acknowledgment, and observed game input. Confirm one mapped event per physical press and verify that disabling Steam Input restores physical mapping. [Hosted input observer](../docs/XBOX-DIAGNOSTICS.md#inspect-the-current-games-input)
2. Use a separate native Steam Input caller. Confirm the selected layout, digital and analog actions, and an action-set switch. Include a keyboard and mouse layout on a legacy caller when the client can expose those events. [Steam Input API](https://partner.steamgames.com/doc/api/isteaminput)
3. Exercise a second controller, reconnect, focus loss, and return to Big Picture. Verify that a second controller's overlay gesture leaves the game's primary controller state intact. Record the Steam AppID and build and the Xbox package and runtime builds. [Xbox verification guidance](../AGENTS.md#verify-before-counting-coverage)
