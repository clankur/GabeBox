# Remaining Steam startup latency

Three cold process activations on Xbox Series X OS `26100.9673` reached native `gamepad-ready` in 52.219, 52.094 and 54.354 seconds on `1.0.231.25`. The corrected `1.0.232.3` package reached the same checkpoint in 15.234, 14.757 and 12.055 seconds. The median fell from 52.219 to 14.757 seconds. Each corrected run authenticated the remembered Steam account, confirmed 627 licensed AppIDs and initially served 135 named games. The initial title metadata scan took 16 ms in all three runs. The native report on the last run recorded 14 unresolved AppIDs, and the later renderer report marked catalog enrichment complete at 23.269 seconds on the account page clock. The served count was still 135. Device Portal's full-output capture returned HTTP 500 in all six timing runs. The timings establish the native checkpoint. The comparison uses the signed baseline APPX SHA-256 `fb1f19956fbb2050cea94541729bfa5dc3944d65165feb1bb2d6f190e3017bb6` and corrected APPX SHA-256 `a1be4f576e69541884ab77ca1e4e5be0fa8cd46244cd8ea436a4dbeb3740c098`. The failed `1.0.232.0` activation has its own receipt and no comparable interval.

The observer's activation-to-ready elapsed time exceeds the account-page elapsed time by 1.711–1.988 seconds. This difference includes work before the JavaScript timer starts and remote observation delay. Its current data cannot divide those costs. Prospective savings below can overlap.

## Follow-up experiments

1. **Overlap profile-specific WebView2 creation with licensed AppID enumeration.** This is the largest measured overlap opportunity. The account was known 1.250–1.750 s before the license list, while the controller and bootstrap consumed several later seconds. Add native timestamps immediately before and after `CreateWithOptionsAsync`, `CreateCoreWebView2CompositionControllerAsync`, adapter read, document-created script installation and `Navigate`. The existing navigation stage begins before the adapter read. Start an experimental detached controller as soon as Steam confirms the same account, withhold signed navigation and broker access until the account and catalog are confirmed, and cancel the preparation on any account change or failure. Test whether overlapping startup adds CPU or memory pressure that delays logon or the first controller frame. Earlier attempts that switched physical windows during warmup lost working-set headroom. Keep the same primary XAML window and preserve the verified account document and the per-account profile. [Native sign-in](../runtime/steam/ProbeNative.cpp) · [Renderer startup](../ui/big-picture-webview/renderer.cpp) · [Previous warmup trials](big-picture.md)
2. **Measure the live Steam license wait before changing callback cadence.** The 250 ms sign-in poll puts a bound on each sampling delay. It cannot explain the entire 1.250–1.750 s from identity to the first positive license count. In a comparison build, record the first connection, first identity match, first license-count call, first positive count, count query duration and callback IDs relevant to those transitions. Keep report payloads free of account data and AppIDs. Compare the existing 250 ms interval with a short 50–100 ms polling window after logon or verified identity. Use an observed license event to wake the same authoritative query if the pinned client supports that path. Valve's `LicensesUpdated_t` does not certify an initial empty list or complete title metadata. Retain the existing deadline, stale credential handling, and live entitlement checks. [Steam callbacks](https://partner.steamgames.com/doc/api/ISteamUser#LicensesUpdated_t) · [Catalog evidence limits](big-picture-reliability.md)
3. **Reduce repeated broker reads during the boot window.** The candidate took 629–726 ms between the first UI Cloud cache index receipt and the last namespace-file receipt. The cache serializes work and performs two account requests per cache document. The account page also uses an 80 ms poll on the renderer queue. Time renderer submit, host dequeue, WinRT or IndexedDB work, host response and renderer receipt for an allowlisted group of requests. The measurements should identify how much time is spent waiting for the poll and how much belongs to real storage reads. Compare a short startup-only polling interval or a coalesced queue notification first. Evaluate one shared in-flight installed-library read for FriendsUI and the app overview only if the broker trace shows duplicate scans. Keep account checks on cache reads and recheck local installation at Play or Install. [Bootstrap gate](../ui/big-picture-bridge/xbox-core-startup.js) · [Cache bridge](../ui/big-picture-bridge/xbox-cloud-cache.js) · [Host poll](../ui/big-picture-webview/big-picture-webview.js)
4. **Trigger the foreground check when the surface is revealed.** The current renderer samples layout and foreground on a 500 ms timer during normal startup. An immediate scheduled foreground probe after reveal may save part of the consistent 473–555 ms interval. Record `app-initialized`, first actionable DOM observation, visibility change, next composition frame, and successful foreground check separately. Use any renderer event as a wake signal and keep the native check for the actual active window and visible layout. A signed early-reveal comparison can also establish whether a running controller benefits from normal WebView2 memory policy sooner. Verify the visible Library and one controller action before counting a timing win. [Native readiness predicate](../ui/big-picture-webview/renderer.cpp) · [Early-reveal trace](big-picture.md#cached-sign-in-and-big-picture-startup-timing)
5. **Separate bundled asset work from startup presentation.** The pinned `sp.js` is 16,224,005 bytes, and the bundled default movie is 6 seconds long. In each corrected run, All Games was selected 2.310–2.316 s after the first catalog and about 236 ms after the first local namespace continuation. The traces cannot attribute six remaining seconds to the movie. Collect allowlisted `sp.js` and `library.js` resource timings, document load and post-load task duration, the packaged movie's `loadeddata`, `playing`, `ended` and `error` events, the main portal mount, and the first unobscured Library frame. If asset work dominates, trial reading the signed adapter while native sign-in runs and compare the stock local file route on the same profile. If playback actually blocks the first actionable frame, compare the pinned UI's original cancel input with unattended startup. Keep first-time setup and user-selected presentation behavior in both arms. [Movie lookup bridge](../ui/big-picture-bridge/xbox-startup-movie.js) · [Valve UI fixture](../tests/steam-big-picture-shell.cjs)

Add the account-page script-entry timestamp and an Xbox monotonic-clock anchor before browser open. This separates true process-to-script work from Device Portal sampling. Use interleaved cold runs of the current signed package and each individual experiment on the same account and console. Pair `gamepad-ready` with a fresh matching layout capture and a successful navigation input. Record startup failures and retain the first failed operation.
