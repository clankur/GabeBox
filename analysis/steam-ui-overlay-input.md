## Running-game overlay

On `.28`, a keyboard round trip resumed Dwarf Fortress while PID `11680` remained live. `.33` displayed the stock overlay for Slay the Spire, and `.37` displayed its title screen, AppID `646570`. The `.37` host and game were gone before the overlay key could be delivered. That evidence leaves the process-loss cause open. [Game and overlay results](big-picture-reliability.md#direct-native-game-display) · [Running-game controls](big-picture.md#background-steam-and-the-running-game)

The shared WWA host consumes the return callback before invoking it. It restores the callback on rejection, while a presenter may also resolve `false` after declining a handoff. That second path leaves a live title with no Resume target. Keep callbacks with their running game until the view transition succeeds. Serialize Resume and ensure that a concurrent process exit can complete its return to the library. Record the declined and rejected handoffs in the existing report. [Overlay host](../ui/big-picture-webview/big-picture-webview.js) · [Presenter callbacks](../ui/signin/steam-sdl-native-view.js)

A secondary view switch or primary panel visibility failure during Resume can occur after the game has already presented. The presenter can preserve its running resources and return focus to Steam for a retry. The secondary presenter clears its overlay request only after the view switch resolves. An initial view creation failure or a terminal presenter error still uses the existing fallback. [Presenter callbacks](../ui/signin/steam-sdl-native-view.js)

On the new signed runtime, launch an owned game through stock Play and use a physical controller to open its overlay and reach Library. Select stock Resume and observe the same game PID and advancing presenter counters. Open the overlay again, confirm stock Exit, observe the process exit, and verify normal Library navigation. Repeat with another presenter or title. Record Xbox model, OS build, app package, Steam AppID and build, and the first failed operation. ## Steam Input controller settings

The `.33` Slay overlay displayed “No controller connected.” In the pinned UI, `ControllerConfigStore.Init` synchronously registers six config events before subscribing to typed controller inventory changes and querying the current list. The stock Chromium fixture stops at the missing first registration. Its separate `ControllerStore.Init` also stops before its device query because the adapter rejects the initial hardware accessibility string request. The game presenter receives physical controller samples through the shared host protocol. [Stock fixture](../tests/steam-big-picture-shell.cjs) · [Input bridge](../ui/big-picture-bridge/xbox-input.js) · [Controller list service](../ui/big-picture-bridge/xbox-controller-service.js)

Complete the subscriptions so the stock configurator can attach to the existing controller inventory. A typed empty list completes the optional hardware accessibility request so the main controller store can continue to its inventory query. The Xbox host currently has no Steam configuration event source. Leave those listeners idle, return an explicit unavailable result for the stock selected-layout query, and invalidate per-slot config state when a physical device disconnects or a different identity replaces it. This enables device discovery and preserves Valve's failure handling for the unavailable configuration source. Steam-owned remapping still requires observing Steam's selected layout and its game-facing output, or its action API, on Xbox. [Valve Steam Input API](https://partner.steamgames.com/doc/api/isteaminput)

Use an owned legacy gamepad title and a separate native Steam Input caller. Confirm a real controller appears in Controller settings and disappears on disconnect. For remapping, swap A and B with Valve's layout editor, launch with stock Play, and match the selected layout, source slot, applied input and game response. Verify the physical mapping again after disabling Steam Input. For the native caller, verify digital and analog actions and an action-set change. Document any unavailable operation or missing native source at the first boundary where it occurs. [Steam Input console procedure](steam-input.md#console-verification)

This session had no visible physical controller inventory, so discovery, disconnect and remapping remain open on hardware.
