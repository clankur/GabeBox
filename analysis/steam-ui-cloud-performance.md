# Steam Cloud backups and gameplay performance

## Steam Cloud

[Issue #56](https://github.com/clankur/GabeBox/issues/56) calls for versioned, read-only downloads through the Xbox library. Its [Series X follow-up](https://github.com/clankur/GabeBox/issues/56#issuecomment-7065824445) records a real download and a restore into an isolated Slay the Spire fixture. That trial established the retained Steam session, the pinned `SteamClient023` unified-message interface, the file listing and the verified HTTPS transfer for AppID `646570`. The Steamworks partner OAuth interface requires separate app-scoped authorization. [Direct Steam Cloud research](../docs/STEAM-CORE.md#direct-steam-cloud-research)

`StageSteamCloudFiles` enumerates one owned AppID, enforces file and response limits, and verifies bytes and SHA-1. The original caller dispatched to Slay the Spire's save-folder restore and deleted the download staging folder. The Big Picture UI settings cache handles UI preferences. Stardew Valley's live save paths and remote file layout remain unverified. [Cloud transfer](../runtime/steam/SteamCloudTransfer.h) · [Cloud action status](../ui/signin/steam-cloud.js)

Verified transfers publish a backup under the active Steam account and AppID. The manifest preserves original cloud paths, byte counts and checksums with the numbered payloads. A folder rename publishes a complete snapshot. Remote paths stay out of file API arguments. The standalone Steam Core library also retains Slay the Spire's existing explicit restore. A signed QA package tied to an approved account can exercise another owned AppID before adding a live restore mapping.

### Loading a Steam Cloud save

A snapshot is an app-local archive. The Slay the Spire launcher gives Java the verified game install directory as both its process working directory and `user.dir`, and the game uses `preferences` and `saves` there. The existing **Download and use saves** operation fetches the current Steam Cloud copy, merges verified files into a staged copy of those folders, then switches the folders under a journal. The previous live folders remain in the backup. The packaged preview probe runs the same save-folder mapping in a temporary fixture and never launches Java there. [Hosted Slay launcher](../runtime/steam/ProbeNative.cpp) · [Transactional restore and preview](../runtime/steam/SteamCloudRestore.h)

The Big Picture dialog for an installed Slay the Spire requires a separate confirmation before applying the current Steam Cloud saves. The prompt explains that matching files are replaced and the previous Xbox folders are backed up. The merge preserves Xbox-only files, including any local-only autosave. Verify the Cloud autosave hashes against the restored active files, then use the game's **Continue** and capture the loaded gameplay scene. An existing matching autosave and a title screen establish file availability and game startup only.
