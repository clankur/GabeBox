# Steam game compatibility on Xbox Series X

These results come from licensed Steam installs under the same Developer Mode app. A complete install, an accepted Steam Play request, a running process, and a usable window are separate observations.

| Game | Last verified result | Fix or next diagnostic |
| --- | --- | --- |
| Dwarf Fortress | The x64 game installed. Steam accepted Play. Adding the signed Microsoft desktop Visual C++ framework changed the captured exit from `0xC0000135` to `0xC0000139`. The Xbox system import probe found `ImmGetIMEFileNameA` missing from the SDL2 dependency chain. Under the same app version, original SDL2 failed with `0xC0000139` and the rebuilt SDL2 2.26.2 reached Steam's process-start checkpoint without a verified window. | The rebuilt SDL2 omits the unavailable import and provides all 117 required SDL2 exports. Capture the startup process result independently of Steam's window poll, then test graphics and audio initialization in a control app if the process gets past the loader. [SDL2 findings and build](https://github.com/clankur/steam-xbox-devmode/pull/29) · [Microsoft loader status codes](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-erref/596a1078-e883-4972-9bbc-49e60bebca55) |

[Developer runtime notes](https://forums.stardewvalley.net/threads/important-announcement-for-modders-stardew-valley-64-bit.8669/) · [.NET host tracing](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-environment-variables#dotnet_host_trace) |

## Download queue

Dwarf Fortress downloaded 1.36 GB and ULTRAKILL downloaded 3.14 GB while Hades and Stardew Valley were paused. Stardew Valley later finished its own transfer. Terminal queue reports for ULTRAKILL and Stardew Valley showed no active download and zero queued entries. During Stardew Valley's transfer the active title was Stardew Valley and no other title was recorded. Steam sometimes reported an active title several minutes before writing transferred bytes to its manifest. [Selected-game retry](https://github.com/clankur/steam-xbox-devmode/pull/25) · [Queue diagnostics](https://github.com/clankur/steam-xbox-devmode/pull/26) · [Transfer measurements](https://github.com/clankur/steam-xbox-devmode/pull/28)

## Reproduce the import control

Pass the local `UnityPlayer.dll` from the installed title to `prepare-steam-core.py --inspect-pe` when preparing a control layout. Repeat the option for additional PE files. The input binaries stay local. The layout contains only the generated import inventory and the probe. Package and deploy the control through the existing CLI, using the same signed VCLibs dependency as the game-launch comparison. Version `1.0.94.0` reported `opengl32.dll_system_load_error=0x0000007E` and the two missing User32 exports. This reports which imports could resolve in the Xbox control process.
